# 人物卡（Character Bible）

目标：让人物像「活人」而非「功能位」，并保证他永远按自己的人设行事。

## YAML 字段卡（每人物一个文件 `characters/人物名.md`）
```yaml
---
id: 林晚
name: 林晚
alias: 阿晚
role: 主角
age: 24
appearance: 短黑发、左眉一道旧疤、常穿墨绿工装
personality: 外冷内热、固执但重情、动手强于表达
goal: 找到失踪的哥哥
motivation: 童年唯一的依靠，执念驱动
conflict: 能力边界 vs 执念，以及信任障碍
arc: 从封闭依赖 → 学会信任他人并承担代价
relationships: { 顾衍: 敌对渐转同盟, 沈姨: 亦敌亦友 }
status: 深陷组织追杀，身心俱疲
---
```
- 字段可增减，但**goal / motivation / conflict / arc / status** 五者必须有：这五个是「人物弧光」与「一致性」的锚点。
- 关系表用 `[[对方名]]` 双链，便于反向查询（对谁有感情债、谁是他死穴）。

## 人物驱动的写作法则
- 行动由 motivation 驱动，不因剧情便利而让角色「突然变聪明/变蠢」（OOC）。
- 每次出场，先查人物卡确认：此刻他的 goal/status 决定他会怎么做。
- 冲突来自 goal 与他人的 goal 相撞，不是作者硬造的巧合。

## 一致性检查（写章节后）
- [ ] 行动是否违背 personality 与现状 status？
- [ ] 关系有没有按 relationships 演进，且与正文一致？
- [ ] 专有名词、称呼、习惯性口头禅是否跨章一致？
- [ ] 有无为凑戏而让角色做出不可能的选择？

## 输出
- 每个主要人物一个 `.md` 人物卡；写作后更新 status（状态）字段。
- 交付时给作者一张「人物-动机-冲突-弧光」速览表。
