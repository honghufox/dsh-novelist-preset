# 章节写作（Chapter Writing）

目标：把大纲要点落成有画面、有推进、可读性强的正文，且不违背故事圣经。

## 动笔前：上下文打包（必做）
把以下四块读进来作为写作上下文，缺一不可：
1. 本章大纲要点（`outline.md` 中该章的 1–3 行）
2. 出场人物卡（`characters/` 对应文件，重点 goal/motivation/status）
3. 相关世界观条目（`worldbuilding/` 对应主题）
4. 尚未回收的伏笔（`continuity-check` 的登记表）与上一章结尾

上下文不足就先用 read / glob 读取故事圣经，不要凭空写。

## 一章的结构
- **开场**：用动作/场景快速进入，不铺垫长篇背景。
- **推进**：本章必须有冲突升级、转折或揭示（至少其一）。
- **结尾钩子**：悬念、反转、新威胁、情感落点，让读者想翻页。
- 每章 2000–3500 字为常见网文基准，可按作者习惯调整；避免一章塞过多事件。

## 草稿 → 修订
- 先写**草稿**（求快、求全，允许粗糙），再**修订**（打磨语言、删冗余、查一致性）。
- 修订重点：删 AI 味套话（仿佛/不禁/一时之间/心下一惊/不由得），删解释性旁白，把「告知」改「呈现」。

## 质量红线（DO / DON'T）
- DO：show, don't tell；动作与对白承载情绪；对话符合人物身份与口癖；每章有目的。
- DON'T：形容词轰炸、空洞内心独白、水文凑字数、头重脚轻、机械指代（他/她复用混用）、章末总结「本章发生了什么」。

## 输出
- 正文写入 `chapters/第NNN章-标题.md`：用 write 新建/覆盖整章；续写时先 read 取出旧稿再写入。
- 交付时：给作者本章正文 + 一句话「本章推进了什么 + 下一章建议」。
- 写完后跑 continuity-check。
